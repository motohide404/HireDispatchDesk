# HireDispatchDesk

社内向けのハイヤー・タクシー配車ボードと、運転者・車両・取引先の台帳を管理するWebシステムです。

## 更新の運用

通常の修正はHALがコード変更、GitHubへの保存、検証、公開反映、公開確認まで担当します。利用者が修正のたびにMacの更新ファイルを実行する方式は終了します。

GitHub Actionsに、PRの検証と、mainの検証済み成果物を既存のテスト環境へ配備する処理を用意しています。固定の更新口からの初回配備は完了しています。**GitHub ActionsのSecrets設定・自動配備の有効化は未完了です。** CI成功を配備成功とは扱いません。

接続先・ホスト鍵・配備用秘密鍵・公開先URL・実環境のコード照合情報はGitに含めません。環境側の設定へ分離します。管理者向けの構成は [deploy/github/README.md](deploy/github/README.md) を参照してください。

## 必須機能と実装状況

### 仕事の表入力（反映済み）

「仕事登録」と、配車ボードの「表でまとめて登録」から開きます。1行1件の表で仕事名・取引先／お客様名・区分・利用日時・終了日・希望車両区分・指定車両／乗務員・見積金額・メモを入力し、確認後に未配車の仕事へまとめて登録します。

- Excelから複数セルを貼り付け、行追加、貼り付けの取消、Tab・Enter移動に対応。初期5行、最大200行。終了が翌日の場合は終了日も入力します。
- 入力不足・不正な日付や金額・不明な指定先をセルへ表示し、入力済みの全行を確認してから登録します。空行は除外します。
- 保存の応答を確認してから入力欄をクリアします。失敗時は入力と登録IDを保持し、同じ仕事を重複させず再試行します。応答だけが失われた場合も登録済みのIDと内容を照合します。
- 画面を切り替えても入力を保持します。下書きは画面内の状態で、ページを閉じたり再読み込みする前には未登録の警告を出します。下書きのサーバー自動保存ではありません。
- 項目は`client/src/lib/jobEntry.ts`の`JOB_COLUMNS`に分離。列順・貼り付け・表示・確認を同じ定義から作ります。将来の任意項目は`extra: true`で追加でき、登録・配車・未配車へ戻す際も引き継ぎます。利用者が画面上で列を設定する機能はまだありません。
- お客様は「台帳から選ぶ」で取引先・拠点・担当者を検索して指定できます。名称・正式名・管理コードの完全一致も照合し、同名が複数ある場合は明示選択を求めます。IDで台帳と結び付け、担当者→拠点→取引先の順に電話・メールを補います。
- 連絡担当者・電話番号・メールアドレスを追加し、電話かメールのどちらかを必須とします。新規のお客様は仕事に連絡先を保存します。取引先台帳への新規登録は、既存の取引先画面で行います。
- 台帳連動中の下書きは台帳の変更を取り込み、仕事ごとに変更した連絡先は保持します。連動解除や別のお客様の貼り付け時には前のお客様の連絡先を消します。登録後は受付時の連絡先を保ち、配車・未配車への返却後も引き継ぎます。配車詳細では電話・メールのリンクと、台帳にある現在の連絡先も確認できます。
- 既存の氏名だけの予約はそのまま利用できます。新しい連絡先と台帳の参照先は、画面と保存APIの両方で検証します。

Node36件・Python38件と本番ビルドが成功。ソースはGitHubへ保存済みです。実ブラウザでの確認と、公開環境への反映は未完了です。

### 点呼簿・出勤簿

職員台帳に運行管理者・選任された補助者・事務員を登録し、記録担当者・点呼執行者をIDで選択します。役割・営業所・選任日を保存し、点呼の当時の氏名・役割・営業所は職員情報の変更後も保持します。事務員・利用停止職員・選任前の職員は新しい点呼の執行者にできません。資格・選任の確認は事業者が行うもので、登録や選択による本人認証・資格の付与は行いません。

有無等の確認は未選択のラジオボタン、測定値は小数3桁までの直接入力に変更。保存前の選び直しは可能で、保存後は元記録を固定して理由付き訂正を追記します。点呼執行者・車両・日時・方法・酒気帯び・検知器使用を共通項目とし、業務前は疾病・疲労・睡眠不足・日常点検・指示事項、業務後は車両・道路・運行状況と交替運転者への通告を分けて入力します。その他必要事項・目視応答確認・検知器状態・点呼場所も記録できます。旧記録の欠落項目は推測で埋めません。


- 点呼担当者が乗務前・乗務後の点呼を入力。同じ勤務IDに出退勤と点呼をひも付け、日またぎ勤務も出勤日で整理します。点呼から出退勤時刻を自動生成しません。
- 点呼日時、執行者、車両、方法、酒気帯び、検知器・測定値、疾病・疲労・睡眠不足、乗務前の日常点検、指示・報告・通告・対応内容を保存します。確認結果は空欄から明示選択し、未測定を0として扱いません。
- 保存済み記録はAPIでも上書き・削除を拒否。追記・訂正・取消は記録者・理由を付けた新しい版として保存し、元の内容を残します。競合時は409で拒否します。
- 日別一覧、以前からの未退勤、詳細・履歴、月別の点呼簿／出勤簿／履歴CSVに対応。CSVの数式として解釈され得る文字列は無害化します。
- 出勤簿は実際の出退勤の記録です。休憩控除、労働時間・残業・給与計算は未実装。共通ログインのため、職員台帳からの氏名選択は本人認証ではありません。
- 記録項目の参照：[国土交通省・旅客自動車運送事業運輸規則の解釈及び運用（第24条）](https://www.mlit.go.jp/jidosha/anzen/03safety/resourse/data/construction_ryokaku.pdf)。この機能による自動点呼や検知器連携は実装していません。

### 台帳機能

- 乗務員の顔写真：JPEG・PNG・WebP、5MB以内。選択後のプレビューと保存確認を挟み、一覧にも表示します。変更時は「この変更を保存しますか？」と氏名・変更前後を表示し、戻る・キャンセル・画像送信失敗では現在の写真を保持します。
- 適性診断：受診日・区分・機関・所見・次回予定日を履歴として登録・編集します。最新の受診記録の次回予定日を一覧と詳細へ表示します。予定日は手入力で、法令による自動算出は実装していません。
- 取引先別タリフ：取引先ごとに複数の料金条件、税区分、値引き・キックバックの率／定額、期間・補足を保存します。予約・請求への自動適用は未実装です。
- 車両区分：新規・既存車両とも自由入力し、配車ボードへ引き継ぎます。従来の区分名も保持します。
- 免許期限：60日以内／1か月以内のカードをクリックして一覧を絞り込みます。検索欄の上に条件・人数・解除ボタンを置き、一覧と詳細に期限・残り日数・当日・期限切れを表示します。

1か月は日本時間の当日から翌月の同日までとし、同日がなければ翌月末までです。期限切れ・未登録は将来の期限人数から除外し、アーカイブの選択をカードと一覧の両方へ反映します。解除ボタンは期限条件と検索文字を消し、アーカイブ表示の選択は保持します。

これらの画面機能は既存テスト環境へ反映済みです。実ブラウザでの全操作の確認は未完了です。顔写真の切り抜き・位置調整・拡大縮小は提案段階で、今回の実装には含みません。

## 保存と認証

React／TypeScript／Vite、Python API、PostgreSQLを使います。小規模な社内テスト向けに、業務データはJSONBの共有ワークスペースとして保存し、同時編集の古いrevisionは409で拒否します。添付画像の表示にもログインが必要です。

テスト環境は共通ログインです。個人別の権限・監査、確定売上・給与計算、請求書発行、外部配車アプリ・メール・決済との連携は未実装です。サンプルを使う開発・検証向けで、実顧客の個人情報は入力しないでください。

## 開発・検証

```sh
npm ci --prefix client
npm test --prefix client
python3 -m unittest discover -s tests -v
npm run build --prefix client
```

Nodeの検証は、保存・日付・金額と、実Reactコンポーネントを用いたDOM操作を確認します。実ブラウザでのレイアウト・画像デコードを含む操作とは区別します。実ブラウザ用テストは `cd client && npm run test:e2e` です。

CIは同じ検証済み画面とAPIから配備物を生成します。配備先は専用鍵で固定の受信処理だけを実行し、コード照合、DB・旧コードのバックアップ、一時DBでの検査、再起動、業務データ保持、公開ファイルの一致を確認します。失敗時は旧コードへ戻します。
